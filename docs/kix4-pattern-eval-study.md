# kix4 研究报告：边角实现的问题 + 模式权重模型能压到多小

> 对象：<https://github.com/suulnnka/kix4> —— 同一个作者的旧黑白棋引擎（Lua，PVS + 模式评估，2016-12 ~ 2017-01，三个文件 766 行）。
> 方法：全文移植到 Node（`kix4.mjs`），用**独立 2D 朴素实现**对拍规则/翻子/模式编码；再自对弈训出真实权重书，做对称折叠 + 量化 + 打包实测，最后**用对局验收**。
> 所有结论都有脚本可复现（见 §7），正文不堆代码。

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 规则、翻子、计数、模式编码、增量模式维护、残局完全搜索 | **全部正确**（穷举 + 对拍，0 项失败） |
| 边角实现的真正问题 | **不在正确性，在建模取舍**：角被和 X 位、C 位绑进同一张 6 格表；16 条边线各占一张 3^8 表、不做任何共享（占模型 78% 体积）；学习时 38 张表拿到的更新量完全相同 |
| 搜索层 | 2 个已验证的缺陷：「排序用层数当盘面阶段」+「阶段表下标 0 / 7 越界路径」，另有若干粗糙处 |
| 模型规模 | 133,974 参数/阶段 × 6 阶段 = **803,844 个权重**；float32 落盘 3.14 MB，原版文本落盘 **15.5 MB** |
| **对称折叠** | **14.14×**：133,974 → 9,475 项/阶段（其中 248 项被对称性强制作 0）。**六阶段 803,844 → 55,362** |
| 为什么是 14.14× 而不是 8× | 权重是**黑方视角**存的 ⇒ 对称群是 `D4 × 换色`，**16 元**（不是几何的 8 元）。符号约定可从 `learn()/evaluate()` 直接**推导**，不需要拟合 |
| 对称性用满了没有 | **用满了，没有第 17 个镜像。** 左右/上下/旋转都是 D4 的成员，黑白反转是独立因子 `C2`；三条独立证据：16/16 元素实测把 38 张模式映回自身、**Burnside 引理与并查集两条算术路径都给 9,475**、**对 38 张模式超图穷举自同构 = 8（= |D4|）** |
| 顺带发现 | 折叠不只省体积，**还涨棋力**：折叠 + int8 对不折叠 float32 打出 **71.5% 胜率 / +18.7 子** |
| 另一处建模更正 | kix4 的 38 张表**不是**"8 行 + 8 列 + 22 条斜线"，而是 **16 条满线 + 18 条斜线 + 4 个「角落三角」**（每个 6 格、非共线）。这也解释了为什么"每格恰好被 4 张覆盖" |
| 最差的一笔交易 | 「丢掉 6 张斜线/对角线 + 角三角、只留 4 条边线」：体积只省 27%，一致率掉到 **37.3%** —— 不如直接降到 int4 |

**"最低能压到多大"——按愿意付出的棋力代价分档（全部实测，对局验收同深度 mid=6/end=12）：**

| 档位 | brotli | gzip | 实测棋力代价 |
|---|---:|---:|---|
| 折叠 + int8（每表定标，6 阶段） | 16.70 KB | 18.85 KB | 免费（对折叠 float32 48.6% / −0.02 子） |
| 折叠 + int8（全局定标，6 阶段） | 10.28 KB | 11.98 KB | **免费**（对每表定标版 47.3% / −0.40 子） |
| 折叠 + int6（每表定标，6 阶段） | 12.55 KB（稀疏 10.03） | 13.54 KB | 免费（48.3% / −0.78 子） |
| **折叠 + int8（全局定标，2 阶段「从零训」）** | **4.85 KB** | **5.63 KB** | **基本免费**（对 6 阶段模型 49.0% / −1.73 子） |
| 折叠 + int4（每表定标，2 阶段「从零训」） | **2.19 KB** | 2.37 KB | 未对局（int4 在 6 阶段实测约 −2.7 子） |
| 折叠 + int4（每表定标，1 阶段） | **1.06 KB** | 1.16 KB | 未对局（自身一致率 77.1%） |
| 折叠 + int4（6 档平均成 1 档） | **0.74 KB** | 0.79 KB | 未对局（一致率 73.7%） |

**一句话：** 这个模型设计得很"重"（803,844 个权重，78% 花在 16 张互不共享的边线表上），但对称冗余极大 ——
把 `D4 × 换色` 用满就是**免费的 14.14×**，而且这一步顺带把棋力打高了 18.7 子。
再叠上 int8 + 全局定标（两项都实测免费）和"阶段数 6→2 并在训练时定死"（实测 −1.7 子，噪声内），
**整个模式评估模型落点是 4.85 KB（brotli）/ 5.63 KB（gzip）** —— 相对原版文本 15.5 MB 是 **约 2800 倍**。
想更极端（没人验收过棋力）：int4 + 1 阶段可以做到 **1 KB 上下**。
上一轮只用了几何的 8 元折叠（7.2×）并据此判断"必须动 int4 才能进 35 KB 预算"——**完全不需要**。

## 1. 代码结构

| 文件 | 行数 | 作用 |
|---|---|---|
| `kix.lua` | 689 | 全部逻辑：棋盘 / 模式评估 / 搜索 / 学习 / 存盘 |
| `learn.lua` | 34 | 自对弈训练驱动（1000 轮 × 30 局），每轮写盘 |
| `play.lua` | 87 | 终端人机对弈 |

- **棋盘**：一维表 91 格，`index = x*9 + y + 1`（相邻行差 9、相邻列差 1）；非格子下标全部填哨兵 3。
  ⚠️ 是 **9×9 的数组**：第 0 行、第 0 列是哨兵，真正可下的只有 `x,y ∈ 1..8` 共 **64 格**。
  （这一点很坑：做对称群分析时若把 81 格都当顶点，那 17 个哨兵格不在任何模式里、彼此完全等价，
  会凭空多出一堆"对称性"，把穷举搜索直接撑爆。见 §3.A2 的复核。）
- **模式（评估特征）**：38 张表，`1-8` 是 8 条**行**、`9-16` 是 8 条**列**、`17-27` 与 `28-38` 是两组各 11 张。
  注意两组斜线里**各混进了一张「角落三角」**（非共线的 6 格角块），所以准确构成是：
  **16 条满线（长 8）+ 18 条斜线（两个方向各 9 条，长度 4,5,6,7,8,7,6,5,4）+ 4 个角落三角（每个 6 格）**。
  按格点算覆盖次数：`16×8 + 2×(4+5+6+7+8+7+6+5+4) + 4×6 = 128 + 104 + 24 = 256 = 64×4`
  —— 这正好解释了"每格恰好被 4 张覆盖"。
  每张表规模 `3^len`（空/黑/白三态），`len` 最大 8。
- **搜索**：PVS「重搜式」写法（`search_evaluate` / `search_exact`）+ 按阶段选权重表。
- **学习**：类 TD(0) —— 拿搜索分与当前评估分之差，给**全部 38 张模式**各加一个相同的量。

## 3. 问题 A：边角怎么被切进模式里（建模取舍）

### A1. 角、C 位、X 位被绑在同一张 6 格表里

模式 17 的方格（`A`=最低位）：

```
模式 17 (3^6 = 729 状态)   次序: 11 12 13 21 22 31
   ABC . . . . .
   DE  . . . . .
   F   . . . . .

模式 27 = 右下角   模式 28 = 右上角   模式 38 = 左下角（同一形状，只差置换）
```

**左上角 (1,1)、两个 C 位 (1,2)/(2,1)、X 位 (2,2)、外加两个更远的格 (1,3)/(3,1)，共用一张 729 项的表。**
黑白棋里"角 ≈ +巨大、X 位 ≈ 负资产"方向相反，这个切法把它们塞进同一张表：
模型想表达"角被占了所以好"，只能通过一个 6 格联合状态表达，和 X 位占不占混在一起。
再叠加 A4 的更新规则，角一旦翻转，这张表里 5 个无关格子的权重也一起被改。

（注：模式的**几何**是 D4 对称的，4 个角的三角表两两同构 —— 所以这不是"算错"，是"切得不好"。）

### A2. 16 条边线各占一张 3^8 表，却表达同一个函数 —— 以及该怎么折叠

`1-8`（行）+ `9-16`（列）= 16 张 6561 项的表 = **每阶段 104,976 项，占整个模型 78.4%**。

#### 对称群是 16 元，而且符号可以推导出来

关键一步：**kix4 的权重表存的是"黑方视角"的值函数**，证据就在代码里：

```lua
-- evaluate(): score 是"走子方视角"
return color == 1 and score or -score

-- learn(): 明确把 diff 翻回黑方视角再更新
if color == 2 then diff = -diff end
```

于是"黑方视角的价值"这个目标函数有**两条精确对称性**：

| 操作 | 对价值的约束 | 对权重的约束 | 符号 |
|---|---|---|---|
| 几何 g（8 个棋盘对称） | `V(g(b)) = V(b)` | `w[g(p)][m_g(s)] = w[p][s]` | **+1** |
| 换色 c（黑白互换） | `V(c(b)) = −V(b)`（子差整体取负） | `w[p][补(s)] = −w[p][s]` | **−1** |

两者独立 ⇒ 作用在权重数组上的是 **`D4 × C2`，16 元群**，特征 `sign(g,ε) = (−1)^ε`。

> **上一轮的弯路**：想用"训练残差"去**测**符号（`probe-sign.mjs`），被噪声底淹没判不出来。
> 方向错了 —— 符号不是统计量，是写在 `learn()/evaluate()` 里的**约定**，读代码就能定。
> 本轮还顺手把另一个候选（换色取 `+1`）实测了：它会让评估 σ 从 8.6 塌到 **1.24**（信号自相消），
> 直接反证 `−1` 才是对的。**推导 + 反证，两条路子一致。**

#### 折叠后的精细结构（可与组合公式对账）

按 16 元群作用在 `(表 p, 3 进制下标 s)` 上做带符号并查集，轨道数 = 自由参数数：

| 线长 | 原始项数 | 折叠后 | 倍数 |
|---|---:|---:|---:|
| 8（4 条边线轨道 + 主对角线） | 5 × 6561 = 32,805 | 5 × 1681 = 8,405 | 3.90× |
| 7 | 2,187 | 574 | 3.81× |
| 6（一条长度 6 对角线 + 角三角 3^6） | 1,458 | 401 | 3.64× |
| 5 | 243 | 70 | 3.47× |
| 4 | 81 | 25 | 3.24× |
| **合计** | **133,974** | **9,475** | **14.14×** |

长度 8 那张表的 1681 不是凑出来的，正好是**精确组合数**：

```
长度为 8 的三态串，在 ⟨反转, 换色⟩（4 元群）下的轨道数
  = (3^8 + |反转不动点| + |换色不动点| + |反转∘换色不动点|) / 4
  = (6561 + 81 + 1 + 81) / 4 = 1681      ✓ 与实测一字不差
```

—— 这个对账本身就是"符号约定与群作用都实现对了"的独立证据。

**另外白捡一条结构事实：248 个轨道被对称性强制为 0**（约占自由度的 2.6%）。
例：一条 `BWBWBWBW` 的边线，换色后变 `WBWBWBWB`，再反转回来还是 `BWBWBWBW` ——
而换色要取负、反转要取正 ⇒ `w = −w` ⇒ 只能是 0。这类配置根本没有自由度。

#### 四个镜像都用满了吗：两条独立算术路径 + 穷举自同构

"左右翻 / 上下翻 / 旋转 / 黑白反转"不是四个可以分别开关的旋钮，它们是同一个群里的成员：

| 用户说法 | 形式上是什么 | 群里的角色 |
|---|---|---|
| 左右翻 | `(x,y) → (9−x, y)` | D4 的一个反射 |
| 上下翻 | `(x,y) → (x, 9−y)` | D4 的一个反射 |
| 旋转 | `(x,y) → (y, 9−x)` 等 3 个 | D4 的 90°/180°/270° |
| 黑白反转 | 三态数字 `1↔2`、空不变 | **独立的因子 `C2`**，与 D4 对易 |

所以群是 `D4 × C2`，阶 `8 × 2 = 16`。**没有第 17 个** —— 下面用三条互相独立的证据钉死。

**证据 ①：16 个元素确实把 38 张模式集合映到自身**（`probe-group.mjs` 第 ① 段，16/16 PASS）。
顺便看清一件事：**几何对称不能跨距离合并**。行 1 只能映到"离边 1 格"的 4 条边线
（行 1/行 8/列 1/列 8），映不到行 2。所以 16 条边线最多折成 4 张，不是 1 张；
想跨距离共享就不是对称，得另外付棋力。

**证据 ②：Burnside 引理与带符号并查集，两条完全不同的算术路径给出同一个数。**

```
#轨道 = (1/|G|) · Σ_{g∈G} |Fix(g)|
```

| 群元素 | 不动点槽数 \|Fix(g)\| |
|---|---:|
| 恒等（保色） | 133,974 |
| 旋转 180°（保色） | 162 |
| 主/副对角转置（保色） | 7,092 ×2 |
| 左右 / 上下镜像（保色） | 648 ×2 |
| 旋转 90°/270°（保色） | 0 ×2 |
| 恒等 + 换色 | 38 |
| 旋转 180° + 换色 | 162 |
| 主/副对角转置 + 换色 | 244 ×2 |
| 左右 / 上下镜像 + 换色 | 648 ×2 |
| 旋转 90°/270° + 换色 | 0 ×2 |
| **Σ 合计** | **151,600** |

`151,600 / 16 = 9,475` —— 与并查集实测的 **9,475** 一字不差。
折叠正确性原先只有"并查集跑出来是 9475"这一个来源；现在是两条独立路径对账。

**证据 ③：直接对「38 条模式超图」穷举自同构，结果 = 8，与 D4 同阶。**

D4 是正方形的全对称群（阶 8）这是教科书结论，但 kix4 用的**不是 8×8 格的全部自然对称，
而是「38 张模式」这个超图结构**，折叠的合法性只依赖"这条置换把 38 张模式映回 38 张模式"，
所以该数的是这个超图的自同构群。直接把 64 个可下格当顶点、38 张模式当超边回溯枚举：

```
38 张模式超图(64 个可下格)的自同构数 = 8(展开 516 个候选)
  1-WL 迭代 1 轮 → 10 个色类,最大类 8 个;色类正好等于 D4 轨道
  ⇒ 恰为 8,与 D4 同阶 —— 第 17 个几何镜像不存在 ✓
```

> 这一步踩了两个坑，都值得记：
> **① 顶点集必须是"至少出现在一条模式里的格子"。** kix4 的棋盘是 9×9 数组，
> 第 0 行/第 0 列是哨兵、不在任何模式里。把 81 格都当顶点时，那 17 个哨兵格彼此
> 完全等价、任何不变量都分不开（色类 17 元），穷举直接搜爆（3000 万节点不收敛）。
> **② 不变量必须对"非直线模式"也良定义。** 38 张表里混着 4 个**角落三角**（6 格、非共线），
> 用"直线上的两个端点"造不变量会在角格上自相矛盾（角格上的 4 条模式里有一条是三角），
> 色类被切成 64 个单点、算出的自同构数变成 1。
> 换成**切比雪夫距离多重集**后，色类立刻等于 D4 轨道，516 个候选就收敛。
> （只有 ① 的剪枝还不够；必须加**前向检查**：每次赋值后把同线未赋值成员的候选集收缩到
> "仍能嵌进某条模式"的格子，候选集空掉即失败。）

#### 少用几个镜像要付多少字节（实测）

`final.mjs` 新加了 `--sub`，可以对同一本训练好的权重书换不同的对称子群折叠到底，
走完整条"折叠 → 去均值 → 量化 → 打包 → gzip/brotli"，所以下面是**实测字节**而不是估算：

| 用的对称 | 群阶 | 轨道/阶段 | 倍数 | 6 阶段 int8 稠密 raw | gzip | brotli | 2 阶段全局定标 gzip | brotli |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 不用（原样） | 1 | 133,974 | 1.00× | 785.00 KB | 135.60 KB | 118.49 KB | 37.15 KB | 31.96 KB |
| 只用黑白反转 | 2 | 67,006 | 2.00× | 392.61 KB | 91.33 KB | 80.46 KB | 22.63 KB | 19.45 KB |
| 只用旋转 180° | 2 | 67,068 | 2.00× | 392.98 KB | 85.94 KB | 75.59 KB | 21.50 KB | 18.58 KB |
| 只用 4 个旋转 | 4 | 33,534 | 4.00× | 196.49 KB | 52.00 KB | 46.08 KB | 13.70 KB | 11.93 KB |
| 左右+上下+180°（Klein 四元群） | 4 | 33,858 | 3.96× | 198.39 KB | 51.60 KB | 45.68 KB | 13.57 KB | 11.69 KB |
| 8 个几何对称 | 8 | 18,702 | 7.16× | 109.58 KB | 31.10 KB | 27.53 KB | 7.88 KB | 6.77 KB |
| **8 几何 × 换色 = 16（本报告）** | **16** | **9,475** | **14.14×** | **55.52 KB** | **18.64 KB** | **16.65 KB** | **4.55 KB** | **3.94 KB** |

几个可以直接读出来的事实：

- **用户提的四种镜像全都已经在用，而且一个都没漏。** 只做左右+上下+180°（Klein 四元群）≈ 3.96×、
  只做 4 个旋转 = 4.00×、做到几何 8 个 = 7.16×、再加黑白反转 = 14.14×。
- **几何部分到 D4 就封顶了**（穷举自同构 = 8），再想省只能靠"跨距离共享权重"——
  那不是对称，是近似，得单独付棋力（§5.3 的 `LINEONLY` 档就是这条路，37.3% 一致率，很差）。
- **换色那一半是"纯赚"**：不增加任何建模假设（它本来就是把黑白镜像的同一个游戏），
  单独贡献 1.97×。
- **只用旋转 4 个（4.00×）略优于 Klein 四元群（3.96×）** —— 反直觉但合理：
  Klein 群里左右/上下镜像的不动点多（8 张表被固定），轨道反而没那么精细。

### A3. 注释把行/列说反了

```
-- 1-8 col1-8
-- 9-16 row1-8
```
实测 `ptn2pos[1] = {11..18}` = 顶行（固定 x）。**1-8 是行、9-16 是列**，与注释相反。

### A4. 学习时 38 张表的更新量完全相同

```lua
local one_diff = step * diff / 38
for i = 1,38 do now_book[i][ now_ptn[i] ] = ... + one_diff end
```

角 (1,1) 从空变黑，会同时修改：行 1、列 1、角三角、主对角线 —— 四张表各加同一个数，
其中三张表里的其余格子和这个角毫无关系。信用分配被平摊，是这类线性模式评估的典型粗糙处，
也是角部知识学不准的直接原因。

## 4. 问题 B：搜索层的两个已验证缺陷

### B1. 排序用的权重表是"搜索层数"，不是"盘面阶段"

```lua
local function sort_list(list)
  now_book = ptn_book[ceil( list_top / 10 )]   -- list_top = 当前搜索层数
```

`list_top` 是**回合栈深度**，不是棋子数。中局搜索最大层数 = `mid_depth`（learn.lua 里是 6），
所以 `ceil(层数/10)` 恒等于 1 —— **永远拿"开局阶段表"给中局排序**。
另一个后果：`list_top == 0` 时 `sort_list` 直接返回不排序，而根节点恰好就是 `list_top == 0`，
所以**根节点着法从不排序**。

实测（56 子局面）：盘面阶段应为 6，排序实际用阶段 1。

> 这一条在压缩语境里还有额外含义：阶段 1 的表覆盖率最低（见 §5.1），
> 等于拿"信息最少的那张表"给整个中局排序。

### B2. 阶段表下标 0 与 7 是空表，兜得不一致

阶段表是 `ptn_book[1..6]`，`f = 棋子数 - 4`，`ceil(f/10)` 落在 `0..6`。

| 位置 | 是否兜底 | 触发条件 |
|---|---|---|
| `learn()` | ✅ `if f == 0 then f = 1 end` | — |
| `search_select()` | ❌ 没有 | `mid_depth ≤ 4`（此时 `f = 棋子数 + mid_depth - 4 = 0`）→ 取到空表 → `evaluate()` 崩 |
| `sort_list()` | ❌ 没有 | `list_top ≥ 61` → 取 `ptn_book[7]` |

两条路径都已构造出来并复现（探针 §4）。

### B3. 其他粗糙处

- `learn.lua` 每轮 `write_book("data")` + `write_book("data2")` 内容完全相同，`read_book` 只读 `data`。
- `op_depth` 默认 0 时开局分支是死代码，只有调用方显式 `change_op_depth(6)` 才活。
- `move_list` 按 `64 × 32` 预分配，但合法着法上限 33 个 —— 预分配本身不成立。
- `search_exact` 每层 `depth >= 7` 都重跑一次 `update_all_ptn()`（O(64)），而它本来就被增量维护着。

## 5. 压缩：方法与实测

### 5.1 训练出来的权重书有多"空"

**零初值**（原版是 `math.random()`，全正噪声，不具备可发布性）训练 1500 局自对弈，统计**真正被写过**的表项：

```
阶段 1:   4,721 / 133,974 ( 3.5%)      阶段 4: 32,141 / 133,974 (24.0%)
阶段 2:  14,662 / 133,974 (10.9%)      阶段 5: 36,311 / 133,974 (27.1%)
阶段 3:  24,807 / 133,974 (18.5%)      阶段 6: 21,218 / 133,974 (15.8%)
合计 133,860 / 803,844 = 16.7%
```

**83.3% 的表项从没被访问过。** 原版训练量是 1000 轮 × 30 局 = 30,000 局，量级差 20 倍 ——
所以这份书够做**体积**实验，不够做**棋力标定**（下面每个质量数字都要带这个前提）。

> 初值必须改成 0：原版的 `math.random()` 初值是一条"噪声地板"，
> 未训练项参与量化定标会污染结论，而且那种书根本不可发布。

### 5.2 压缩管线（顺序很重要，两个坑）

```
原始书
 ① 按访问图屏蔽未训练项 → 置 0（零初值下本来也是 0）
 ② 16 元群带符号折叠：value(槽) = sign(槽) × 轨道代表值（只平均"有训练贡献"的成员）
 ③ 每张规范表减去自身均值（每表一个常数，对评估无影响，但大幅压低量化动态范围）
 ④ 量化（可选：每表定标 / 全局定标）→ 稠密或稀疏打包 → gzip / brotli
```

**坑 1（顺序）**：先折叠再屏蔽，会把未训练成员的随机初值**平均进整张表**，误差全是噪声污染。
必须**先屏蔽、再折叠**。

**坑 2（读侧符号）** ★ 这个坑最隐蔽，值得单独写下来：
折叠表里存的是"轨道代表值"，读的时候**必须乘回 `sign(槽)`**。
第一版读侧漏了这一步，于是所有落在换色陪集里的槽（约占一半）符号全反。现象是：

| 观测 | 数值 |
|---|---|
| 几何折叠（全 `+1`，没暴露 bug）与不折叠的评估相关系数 | `0.909` ✓ |
| 16 元折叠（有 `−1` 槽）与不折叠的评估相关系数 | **`−0.079`**（≈ 正交）✗ |
| 对局：16 元折叠档 vs 不折叠 | **8.0% 得分 / −37.6 子** ✗ |
| 同时，"走法一致率" | **99.3%（一切正常）** ← 指标骗人 |

为什么指标看不出来：**参考档和候选档用了同一个（错的）读侧**，误差在两边同时出现、被约掉了。
修好读侧后，相关系数 **0.907**，对局变成 **71.5% / +18.69 子** —— 折叠档反过来把不折叠的基线打爆了（§5.5）。

> 教训：凡是"对称化 + 读回"的管线，必须有一条**独立于折叠本身**的端到端判据。
> 这里用的是两条：(a) 与"不折叠函数"的评估相关系数；(b) 真对局。
> 一般化的说法：**判据要选"与另一条独立链路比"，不要选"自己跟自己比"。**

### 5.3 各档体积实测

权重书 = 零初值 1500 局；`raw` = **真位打包**后的字节数（int6 就是 6 bit/值，int4 半字节）。

| 档位 | 打包 raw | gzip | brotli | 稀疏 gzip | 1 层走法一致率 | RMS/σ |
|---|---:|---:|---:|---:|---:|---:|
| 原版落盘（Lua 文本，每行一个浮点） | **15,503 KB** | 6,963 KB | — | — | — | — |
| float32 稠密（不折叠，6 阶段） | 3,140 KB | 2,823 KB | — | — | — | — |
| 折叠后 float32（不量化，参考档） | 222.1 KB | 89.5 KB | 87.0 KB | — | 100% | 0 |
| **折叠 + int8（每表定标）** | 55.5 KB | **18.85 KB** | **16.70 KB** | 17.56 KB | 99.3% | 0.005 |
| **折叠 + int8（全局定标）** | 55.5 KB | **11.98 KB** | **10.28 KB** | 10.79 KB | 98.1% | 0.012 |
| 折叠 + int6（每表定标） | 41.6 KB | 13.54 KB | 12.55 KB | **11.08 KB** | 97.5% | 0.021 |
| 折叠 + int5（每表定标） | 34.7 KB | 9.45 KB | 8.68 KB | **7.45 KB** | 93.7% | 0.039 |
| 折叠 + int4（每表定标） | 27.8 KB | 4.29 KB | 3.87 KB | **4.13 KB** | 89.8% | 0.070 |

| 折叠 + int4 + 阶段 6→2 | 9.25 KB | 1.66 KB | 1.54 KB | — | 76.8% | 0.258 |

> 最后一行就是"砍特征省体积"这条路：体积只从 18.85 降到 13.79 KB（−27%），
> 一致率却从 99.2% 崩到 **37.3%**。而 int4 只要 4.29 KB 就能保住 90.6%。
> **要省体积应该降位宽，不该砍特征** —— 这条上一轮就测出来过，本轮用修正后的管线复现了（上轮 38.5%）。

**往"完全训练"外推**（1500 局只覆盖 36% 的折叠参数，覆盖率升上去零就没了）：
按量化后**值流**的零阶熵（int8 每表定标 5.06 bit/值、全局定标 3.41 bit/值）× 55,362 个参数：

- 每表定标 int8：≈ **35 KB**（粗上界）
- 全局定标 int8：≈ **24 KB**（粗上界）

所以**稠密列才是"与训练量无关"的硬下限**，稀疏列会随覆盖率增长。上表 10~19 KB 的实测值属于"1500 局的书"。
即便如此，最坏情况（完全训练 + 每表定标 + int8）也仍然在 35 KB 预算内。

### 5.4 三个实测结论

1. **稀疏编码基本没用。** 折叠后仍有 64% 的参数是 0，但显式位图 + 紧凑值相对"稠密直接交给压缩器"**没有收益**
   （int8：17.56 KB vs 18.85 KB gzip）—— gzip/brotli 本来就把成片零压到近乎免费。
   只有压到 int6 以下（值分布本身变窄）稀疏才略占优（int6：11.08 vs 13.54 KB）。
2. **量化到 int8 是免费的。** 对局实测「int8 档 vs 折叠 float32 档」= **48.6%（121/128/1，−0.02 子）**，
   且两者评估相关系数 **1.000**。
3. **全局定标是一个"白捡"的 1.6×。** 每表一个定标能让各表的量化分辨率最优，但量化后的值铺满 ±127、熵高；
   改用整本书一个定标，小表被压成 0/±1，值分布极度集中：int8 从 16.7 KB 掉到 **10.3 KB**，
   而走法一致率只从 99.3% 掉到 98.1%。**代价该由对局来判**（见 §5.5）。

### 5.5 对局验收（唯一可信的判据）

"走法一致率 / 评估 RMS"只是"像不像"，**不是"强不强"** —— §5.2 那个坑就是活证据
（一致率 99.3% 的同时对局 8.0%）。所以每档都要真打。

设置：同深度（mid=6 / end=12 / op=6）、配对开局（同一随机种子跑两局、交换先手）、**关闭学习**
（两方共用同一套全局权重表，不关学习会把对方的书训歪）。
`R1_masked_f32` = 不折叠 + 屏蔽未训练项 + 每表去均值（"可发布但不折叠"的基线）；
`R0_folded_f32` = 折叠后 float32（未量化）；`D6_i8` = 折叠 + int8。

| 对局（A vs B） | A 方得分 | 胜/负/和 | 平均子差 | 结论 |
|---|---:|---:|---:|---|
| `D6_i8` vs `D6_i8`（自对局对照） | 50.0% | 60/60/0 | 0.00 | 对局程序无偏 ✓ |
| `D6_i8` vs `R1_masked_f32` | **71.5%** | 142/56/2 | **+18.69** | **折叠不只是省体积，还大幅涨棋力** |
| `R0_folded_f32`(几何 8 元) vs `R1_masked_f32` | 67.8% | 166/77/7 | +16.63 | 只用几何折叠也赢，但没赢这么多 |
| `D6_i8` vs `R0_folded_f32` | 48.6% | 121/128/1 | −0.02 | int8 量化**免费** |
| `D6_i8g` vs `D6_i8` | 47.3% | 93/104/3 | −0.40 | 全局定标**也是免费的** |
| `D6_i6` vs `R0_folded_f32` | 48.3% | 95/102/3 | −0.78 | int6 也基本免费 |
| `D6_i4` vs `R0_folded_f32` | 47.8% | 94/103/3 | **−2.68** | int4 开始付代价，但只有 ~2.7 子（≈2 SE） |
| `D2_i8` vs `D6_i8` | 42.8% | 83/112/5 | **−5.21** | 阶段 6→2（由 6 档平均而来）代价 ~5 子 |
| `P2_trained`(2 档**从零训**) vs `R0_folded_f32`(6 档) | 48.4% | 118/126/6 | −2.45 | 真 2 档模型只差 ~2.5 子 |
| `P2_trained` vs `D6_i8`(6 档 int8) | 49.0% | 120/125/5 | **−1.73** | 统计上与 6 档模型**无显著差异** |

（200~250 局配对开局：得分标准误 ≈ 3.2~3.5%，所以 47~49% 这一档都还在噪声内；子差标准误 ≈ 1.3 子。）

三条结论：

1. **折叠是"免费的棋力"**：参数少 14.14 倍、体积从 2,823 KB(gzip) 掉到 12 KB，
   同时把不折叠的基线打成 71.5% / +18.7 子。原因是它同时干了两件事 ——
   ① 对称化把训练噪声平均掉；② 未训练槽（占 68%）被对称位置的信息填上，
   等于把训练数据免费放大十几倍。
   （对照：只用几何 8 元折叠对同一个基线是 67.8% / +16.6 子 —— 也赢，但没赢这么多。）
2. **量化到 int8 免费，换全局定标也免费，int6 也基本免费。** 两项无损手段叠加就把 6 阶段模型压到
   **10.3 KB brotli / 12.0 KB gzip**，棋力与"完全不量化"的版本没有可测差异。
   int4 只是 4.3 KB gzip，代价约 2.7 子 —— **如果愿意让这 2.7 子，体积还能再砍一半多。**
3. **阶段数是最便宜的一根杠杆 —— 但必须"从零训"，不能拿 6 档平均。**
   - 拿 6 档训完再平均成 2 档：代价 **−5.21 子**（42.8%）。
   - **用 2 档从零训**（`train.mjs --phases 2`）：对 6 档模型 **49.0% / −1.73 子**，统计上无显著差异；
     而体积从 11.98 KB 掉到 **5.63 KB gzip / 4.85 KB brotli**。
   原因很直白：2 档时每张表拿到 3 倍的训练更新（覆盖率从 16.7% 涨到 **26.4%**），
   而"平均"只是把已经学歪的 6 张表糊在一起。**结论：阶段数在训练时定死，别事后合并。**

   2 档模型（从零训，1500 局）量化后的全部体积：

   | 2 档模型档位 | 打包 raw | gzip | brotli | 自测一致率 |
   |---|---:|---:|---:|---:|
   | int8（每表定标） | 18.51 KB | 8.65 KB | 8.01 KB | 99.7% |
   | **int8（全局定标）** | 18.51 KB | **5.63 KB** | **4.85 KB** | 98.4% |
   | int6（每表定标） | 13.88 KB | 6.69 KB | 6.36 KB | 97.5% |
   | int4（每表定标） | 9.25 KB | **2.37 KB** | **2.19 KB** | 89.9% |
   | 1 档 int8 | 9.25 KB | 4.67 KB | 4.38 KB | 79.7% |
   | 1 档 int4 | 4.63 KB | **1.16 KB** | **1.06 KB** | 77.1% |

### 5.7 顺带验证：对称折叠的"收益"来自哪一半

`--sub geom8`（等价于旧的 `--no-swap`）可以只留几何 8 元折叠（18,702 项/阶段）。与 16 元对照：

- 两个折叠出来的评估函数相关系数 **0.989** —— 功能上几乎同一件事；
- 对同一个不折叠基线的对局：16 元 **71.5% / +18.69 子**，8 元 **67.8% / +16.63 子**。
- 但参数少一半（9,475 vs 18,702），体积也就少一半（§3.A2 的表里是 18.64 KB vs 31.10 KB gzip）。

所以**换色那一半是"纯赚"**：棋力几乎不变（差异在噪声内），参数直接砍半。
这在结构上也说得通：换色折叠把同一形状的"黑优势"与"白优势"两种配置配对，而它们本来就该互为反号。

### 5.6 与"上一轮结论"的差异（如果之前看过那份笔记）

| 项目 | 上一轮 | 本轮（修正后） | 原因 |
|---|---|---|---|
| 对称群 | 几何 8 元 | **`D4 × 换色` 16 元** | 权重是黑方视角存的，换色也是对称；符号可从 `learn()/evaluate()` 推导 |
| 折叠倍数 | 7.29×（18,378/阶段） | **14.14×（9,475/阶段）** | 少用了一半对称性；另：**18,378 / 7.29× 这两个数本身是错的**，见下 |
| 强制为 0 的参数 | 324 个（来源可疑） | **248 个**（有构造性解释 + 换色固定点独立数出 1,782 个槽落在 248 个轨道里） | 上一轮把符号按"是否保初始四子"分配，多出假约束 |
| 折叠是否涨棋力 | 是（56.8% / +3.79 子） | **是，而且幅度大得多（71.5% / +18.69 子）** | 对称性用满 + 零初值书 + 读侧符号修正 |
| int8 体积（6 阶段） | 68.8 KB gzip | **18.85 KB（每表定标）/ 11.98 KB（全局定标）** | 折叠 2× + 零初值书更稀疏 + **真位打包** |
| 35 KB 预算 | "必须动 int4" | **int8 就够，还余 2/3** | 上面几项叠加 |
| 稀疏编码 | "完全没用" | int8 时没用，**int6 以下才划算** | 位图开销 vs 值分布宽度 |
| 参考档怎么选 | 曾经用"原始域屏蔽"（错的） | **必须用"折叠后 float32"** | 否则量到的是折叠误差，不是量化误差 |
| 阶段数能不能砍 | "6→2 阶段再减半"（估算） | **从零训 2 档只差 1.7 子，体积 5.6 KB gzip** | 事后平均差 5.2 子；必须在训练时定 |

> **"18,378 / 7.29×" 是怎么回事**：那一轮用的是"几何 8 元 + 整张表取代表"的口径，
> 而且把它写成了 18,387（= 36,774 的一半），再扣 9 个强制 0 得 18,378，于是算得 7.29×。
> 实际对账（`reconcile.mjs`）：`fold.mjs` 导出的 `FOLDED_PER_PHASE = 36,774`，
> 是「38 张表折成 10 张代表表」的**项数和** ⇒ 133,974 / 36,774 = **3.64×**；
> 它没有合并代表表**内部**的对称（例如一条线表的"前后翻转"稳定子阶为 2）。
> 只要下沉到**槽级**折叠，几何 8 元就是 18,702（7.16×），16 元是 9,475（14.14×）。
> 三个数各有各的口径，混着比就会得到 7.29× 这种不存在的值。

## 6. 对 AetherWebOS 的建议

1. **体积完全够用，而且不需要 int4。**
   `tools/check-size.mjs` 卡的是 **gzip**。折叠 + int8 + 全局定标 = **12.0 KB gzip / 10.3 KB brotli**，
   对局验收与"完全不量化"无可测差异（47.3% / −0.40 子），在 35 KB 引擎闸门里只占三分之一。
   上一轮"必须动 int4"的结论是因为只用了几何的 8 元折叠（少了一半）。
   就算训练到 100% 覆盖、把稠密表全发出去，外推也只有 24~35 KB，仍在预算内。
   如果还要更小：2 档模型是 **5.6 KB gzip**（代价 1.7 子，噪声内），int4 是 3.9 KB（代价 ~2.7 子）。
   两者叠加（2 档 + int4）是 2.4 KB gzip。
2. **别搬 kix4 的模式切法，反过来按体积设计特征集。**
   38 张模式（尤其 16 张不共享的边线表）是"离线训练 + 只看棋力"的产物。要在浏览器里发布，
   应该先按体积定特征集，再训练 —— 反正对称折叠会再把参数砍 14 倍。
   角部要单独给特征（3×3 角块或至少把角/C 位/X 位分开），别沿用 A1 那张混在一起的 6 格表。
3. **阶段数在训练时就定死，别事后合并。**
   用 `train.mjs --phases 2` 从零训 2 档，对 6 档模型只差 1.7 子（噪声内），体积却从 12.0 KB 掉到 **5.6 KB gzip**。
   如果只做体积预算，这是性价比最高的一刀 —— 比 int4 划算（int4 省得多但掉 2.7 子）。
4. **若要复用 kix4 的学习逻辑**，§3-A4 的"38 张表同量更新"应改成按特征数归一，
   否则角部知识会被稀释。
5. **落地口径**：先在有 Vite 的开发服务器上跑 3D 棋盘 + 引擎 worker，
   权重表以 int8 全局定标 + gzip 的形式塞进引擎 worker chunk（现有闸门按 worker 里的
   `ENGINE_TAG` 认 chunk，加一份权重书要同步更新 `tools/check-size.mjs` 的引擎表）。

## 7. 复现方式

研究代码在 `C:\Users\thhid\fun\_research\kix4\`（不在本仓库内）：

| 文件 | 用途 |
|---|---|
| `kix4.mjs` | kix4.lua 的忠实 JS 移植（保留原实现语义与可疑处，差异只写在注释里） |
| `ref.mjs` | 独立 2D 朴素实现对拍基准 |
| `probe-rules.mjs` | 棋盘 / 规则 / 翻子 / 计数 / 模式编码穷举 / 增量模式 对拍 |
| `probe-search.mjs` | 残局搜索对拍暴力 negamax、根层贪心、阶段表选择、越界路径复现 |
| `probe-symmetry.mjs` / `probe-sign.mjs` | 试图用残差"测"换色符号的两个**失败**尝试（结论：符号该从代码推导，不该统计） |
| `probe-group.mjs` | **对称群复核**：16 元作用验证 / Burnside 引理对账 / 强制 0 轨道 / 子群扫描 / 超图自同构穷举 |
| `reconcile.mjs` | 对账 `fold.mjs` 的 36,774（整表代表）与槽级轨道数 18,702 / 9,475 三个口径 |
| `train.mjs` | 自对弈训练 + 访问覆盖统计。`--zeroinit` 零初值、`--phases n` 改阶段数 |
| `fold.mjs` | 几何 8 元折叠的轨道/映射（`final.mjs` 用它复用 `mapTable`） |
| `final.mjs` | **主分析**：16 元群折叠 + 量化 + 打包扫档 + 展开导出；`--sub` 换对称子群 |
| `cmp.mjs` | 比较两份权重书在同一批局面上的评估 σ 与**相关系数**（判"折叠有没有毁掉函数"） |
| `expand.mjs` | 把 n 阶段的书展开成 6 张表（`n < 6` 时对局/分析都能直接吃） |
| `match.mjs` | A/B 对局：配对开局 + 关学习 |
| `quality.mjs` / `compress.mjs` | 前一轮（8 元折叠）的脚本，保留作对照 |

```bash
# 正确性
node probe-rules.mjs && node probe-search.mjs

# 对称群复核（Burnside 对账 + 超图自同构穷举 + 子群扫描）
node probe-group.mjs
node reconcile.mjs          # 36,774 / 18,702 / 9,475 三个口径的逐表对账

# 训练（零初值，6 阶段）
node train.mjs --games 1500 --mid 6 --end 12 --op 6 --zeroinit --out book0.bin

# 折叠结构 + 体积/质量扫档 + 展开成可对局的权重书
node final.mjs book0.bin book0.vis.bin --expand out0
node final.mjs book0.bin book0.vis.bin --dump          # 只看折叠后的轨道结构
node final.mjs book0.bin book0.vis.bin --sub geom8 --dump # 对照：只用几何 8 元

# 各对称子群的体积代价（--slim 只跑三档）
for s in none swap rot180 rot4 klein geom8 full16; do
  node final.mjs book0.bin book0.vis.bin --slim --sub $s
done

# 判"折叠有没有毁掉函数"（相关系数）
node final.mjs book0.bin book0.vis.bin --only-expand --expand outA
node cmp.mjs outA/R0_folded_f32.bin out0/R1_masked_f32.bin

# 对局验收
node match.mjs --dir out0 --games 200 --pairs D6_i8 R1_masked_f32 D6_i8g D6_i8 D6_i4 R0_folded_f32

# 2 阶段模型（本报告推荐档）：训练 → 展开成 6 表 → 对局
node train.mjs --games 1500 --mid 6 --end 12 --op 6 --zeroinit --phases 2 --out book2.bin
node expand.mjs book2.bin book2.vis.bin 2 book2x.bin book2x.vis.bin
cp book2x.bin out0/P2_trained.bin
node match.mjs --dir out0 --games 250 --pairs P2_trained R0_folded_f32 P2_trained D6_i8
```

> 训练速度参考（本机单进程）：6 阶段 2.3 局/s，2 阶段 1.1 局/s（阶段变少后搜索不变、每局略长）。
> 1500 局分别约 11 分钟 / 22 分钟。
