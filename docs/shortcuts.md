# AetherWebOS 快捷键总览

全量盘点(以当前代码为准),来源:`js/system/shortcuts.js`(全局注册表)、
`js/system/desktop.js`、`js/core/`(对话框/重命名/登录)与各应用 / 组件库
(`js/apps/`、`js/lib/`)的 keydown 分支。全仓库无 keypress;唯一按
`e.code` 判键的是电子表格的 Ctrl+5(避开输入法下 `e.key` 的不确定性)。

## 与浏览器默认行为的关系

本项目是纯前端网站,跑在真实浏览器标签页里。**自定义快捷键与浏览器
原生行为不冲突**,机制有三层:

1. **接管处必 `preventDefault()`**。所有与浏览器默认撞车的组合都被显式
   拦截:Ctrl+S(否则弹「保存网页」对话框)、浏览器应用的 Ctrl+T / W /
   D / H / L / 数字、Alt+←/→、F6、F5(系统层拦下并转为刷新桌面图标,
   防误刷丢状态;页面级兜底由会话恢复负责)、编辑器组件的 Ctrl+B/I/K/Z/Y、
   Ctrl+/、以及各处接管焦点移动的 Tab。其中 **Ctrl+W 是最危险的一个**
   (默认会关掉承载整个系统的标签页),浏览器应用已拦。
2. **Ctrl+C / Ctrl+V 天然不打架**。浏览器默认的复制/粘贴作用于「页面
   文本选区」,而系统桌面与应用根容器是 `user-select: none`,常规状态
   没有原生选区,默认动作是空操作。文件级剪贴板(桌面 / 文件管家的
   Ctrl+C/X/V)只在焦点不处于输入框时接管并 `preventDefault`。
3. **输入框内放行原生行为**。input / textarea / contenteditable 聚焦时,
   浏览器原生复制/粘贴/全选照常工作——这正是需要的(从记事本、编辑器、
   终端复制文本出去)。mdedit 组件额外自定义了 paste/drop:拦富文本,
   只插入纯文本。

当前网格态的 Ctrl+C / Ctrl+V 由电子表格自己接管(`preventDefault`):
复制选区值+样式并可跨窗口粘贴,整列选择不接管(仍为空操作);
复制同时尽力把 TSV 写入系统剪贴板,内部剪贴板为空时也可读系统
剪贴板按 TSV 粘纯文本(浏览器不给读权限则静默)。单元格编辑态
(input 聚焦)不接管,原生复制/粘贴照常。

## 维护约定

新增快捷键时:

1. 与浏览器默认撞车的组合(Ctrl+S/T/W/D/L/H、F5/F6、Alt+方向、Tab 焦点
   移动等)必须 `preventDefault()`,否则会触发浏览器原生行为。
2. 需要在「编辑中的输入框」里也生效的(如 Ctrl+S),监听挂在应用根且用
   捕获阶段;只应在非编辑态生效的,先判断焦点是否在输入类元素内。
3. IME 敏感场景(回车提交、字符触发)参考 `core/rename.js` 的
   `isComposing` / keyCode 229 处理,防选词回车误触。
