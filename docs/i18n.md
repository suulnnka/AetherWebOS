# AetherWebOS 国际化(i18n)设计与实施计划

> 状态:**方案定稿,分阶段实施(P0 未开工)**。事实基线为 2026-10 当前代码,
> 涉及的行号与文件均已核对。三项核心决策的定稿理由见 §3、§6、§12。

目标:系统外壳、内置应用界面与应用清单元数据实现中英双语,用户可切换,
默认中文不变。本文既是设计说明,也是逐阶段的施工清单。

## 1. 范围分级:翻什么、不翻什么

| 分级 | 内容 | 说明 |
|---|---|---|
| **翻** | 外壳全部(任务栏/开始菜单/托盘/桌面/登录面板/系统对话框/右键菜单/开机门禁提示)、core 报错与提示文案、lib 工具串(mdedit 工具栏、chl 高亮提示、minimap 控件)、各应用界面 chrome、终端与 vssh 的帮助/输出、清单元数据(name/desc/category) | 即"界面层" |
| **不翻** | 用户文件内容、应用数据(appdata 落盘的一切)、控制台调试输出、`window.WebOS` 接口、vendor 8 个引擎子模块(无界面文案,棋类 UI 在应用层) | 即"数据层";数据层的中文枚举值按 §3 的"值即标识"约定处理 |
| **后置(P3,独立立项)** | 剧情内容:`js/game/` 站点源码与站点元数据、线索链、图寻谜题、邮件/短信种子、vnet 主机树叙事文案 | 量级是几千行"作品文本";机制上走同一套字典(§5),不设技术障碍,只不占本计划工期 |

RTL 不做(zh/en 均 LTR);字典结构预留 `dir` 字段,将来需要再启用。

## 2. 现状盘点(方案的事实依据)

字符串量级(引号内含中文字面量的粗扫计数,含少量注释误报,仅作规模感):

| 层 | 中文字面量 | 备注 |
|---|---|---|
| `js/core/` | ~334 | fs.js/wm.js/vssh.js 最多;含终端远程会话 30+ 命令的帮助文本 |
| `js/system/` | ~125 | taskbar/startmenu/tray/desktop/boot 外壳 |
| `js/lib/` | ~86 | mdedit/chl/minimap 共享组件 |
| `js/apps/` | ~2003 | sheet/browser/chess3d/terminal/bash 各 200+ |
| `js/game/` | ~60 | 剧情站点元数据(P3,不计入) |

关键消费点(逐条对应到代码):

- **清单名是全局显示源**:`manifest.name` 被 wm 窗口标题、任务栏按钮、
  开始菜单磁贴与搜索索引(`js/system/startmenu.js:33`,`data-search` 只收
  `name + id`)、商店卡片、`applink.js` 的快捷方式菜单(`appLinkMenuItems`)
  直接消费;
- **`category` 是身份不是显示**:商店侧栏过滤与计数按中文值相等比较
  (`js/apps/appstore/index.js:75,199,204`),六个值硬编码在 `CATS`;
- **快捷方式文件名 = 清单名**:`applink.js` 的播种/查重/卸载清理全部以
  `a.name + '.app'` 为文件路径键(`ensureDesktopShortcuts` /
  `removeAppShortcuts` / `createAppLink`);桌面渲染时仅去 `.app` 后缀
  (`js/system/desktop.js:19` 的 `displayName`,注释明确"文件管家、终端与
  重命名编辑的仍是真实文件名");
- **日期硬编码 `'zh-CN'`** 散落各应用(memo/mail/clues/weather 等
  `toLocaleDateString('zh-CN')` / `toLocaleTimeString('zh-CN')`);
- **settings 已有语言相关基建**:`settings.set → sys:settings-changed`
  广播、`sortLocale` 排序设置(电子表格消费,本方案不动它);
- **排序**:`registry.list()` 用 `localeCompare(name, 'zh')`
  (`js/core/registry.js:119`);
- **e2e 依赖中文文本**:上百处按 `textContent` 中文找按钮;全部用例默认
  跑中文环境;
- **`index.html` 静态骨架**含少量可见中文(title 提示、搜索 placeholder);
- **中文枚举直接入库的现实**:如 memo 的分类 `['默认','工作','生活','学习']`
  作为值写进笔记数据。同类应用需逐一排查(P1/P2 checklist 项)。

## 3. 核心决策:中文即键(gettext 式)

`t('新建')` 在 zh 下**原样返回键本身**(零字典、恒等函数),在 en 下查字典
返回 `New`;查不到回落键(中文)。不引入 `t('app.memo.btn.new')` 式抽象 key。

理由:

1. **渐进且无风险**:未翻译的字符串回落中文,系统永远可运行;可以一个应用
   一个应用地接入,不需要 130 个文件的大爆炸改写;
2. **e2e 零改动**:默认 zh 下 t() 是恒等函数,现有 60 组按中文文本断言的
   用例全部照旧;
3. **源码可读性不变**:项目母语是中文,`t('删除笔记')` 优于 key 命名,也
   没有"key 与文案漂移"的 review 负担;
4. 抽象 key 方案要求一次性重写全部字符串与 e2e,在本仓库规模下不可行。

代价与兜底:

- **措辞漂移**:改了中文原文,翻译静默失效回落中文 → `i18n:check` 闸门
  对比源与字典,报告"源有译无/译有源无"(§9);
- **运行时拼接串不可作键**:`` `${n} 条` `` 这类模板串必须改写成占位符
  形式 `t('共 {n} 条', { n })`,常见改写模式见 §8;
- **引申约定(重要):持久化枚举值一律以中文值为稳定标识**。与 `category`
  同理——值进数据库/清单作身份,显示层走 t(),比较逻辑用原值。这样存量
   数据**零迁移**(en 用户看到的是 `t('工作') → Work`,过滤下拉的 value
  仍是 `'工作'`)。代价是数据格式与文案耦合:改这类文案等于改数据格式,
  需要显式迁移——本约定下宁可不改。新应用从第一行就守约。

## 4. 运行时模块:`js/core/i18n.js`

归属:`js/core/` 下,经 `vite.config.js` 的 manualChunks 自动进 `'core'`
稳定 chunk;本身只有几十行运行时,无内嵌字典,体积可忽略。依赖
`store.js`(读 locale)与 `bus.js`(广播),与现有 core 叶子模块同级,
不反向依赖外壳。

```js
import { t, tn, registerDict, currentLocale, localeTag,
         onLocaleChange, ready, fmtDate, fmtTime, fmtDateTime } from '../../core/i18n.js';

t('新建')                        // zh:'新建'(恒等)  en:'New'(查字典,未译回落键)
t('共 {n} 条', { n: 3 })          // '共 3 条' / '3 items'({x} 占位符插值)
tn('{n} 条笔记', n)               // 复数预留:字典值可写 { one, other };zh 不需要
registerDict('en', { 新建: 'New' })   // 应用 chunk 载入时注册(§5)
currentLocale()                   // 设置原值:'zh-CN' | 'en-US' | 'auto'
localeTag()                       // Intl 用的 BCP-47 标签('auto' 已解析)
onLocaleChange(fn)                // 订阅(v1 仅 reload 前后生效,见 §6)
ready()                           // boot 期 await:解析 locale、设 lang、按需加载字典
fmtDate(d) / fmtTime(d) / fmtDateTime(d)   // Intl.DateTimeFormat(localeTag()) 封装,
                                          // 替代散落的 toLocaleDateString('zh-CN')
```

- 插值:`String.replace(/\{(\w+)\}/g, ...)`,缺参保留原占位符便于发现;
  约定 UI 文案不出现裸 `{}` 字面量;
- zh 无字典:回落即键,故 `js/locales/` 下只有 `en.js`,不存在 `zh.js`。

## 5. 字典组织与加载

| 字典 | 文件 | 打包 | 加载时机 |
|---|---|---|---|
| core + 外壳 + lib + category 六值的 en | `js/locales/en.js`(**新顶层目录**) | 独立小 chunk | boot `ready()` 里 locale 为 en 才 `import()`——zh 用户零开销 |
| 各应用 UI 的 en | `js/apps/<id>/en.js`,应用 `index.js` 顶部 `import './en.js'`(文件内自 `registerDict`) | 并入该应用 chunk | 随应用 chunk 加载(见下) |
| 清单元数据 | `manifest.js` 的 `i18n` 字段 | manifest 被 manualChunks 强制划进 `'core'` chunk(`vite.config.js:65`) | 启动即有,共 35 应用约 +2KB |

两个刻意的选择:

- **en 总字典不放 `js/core/`**:`manualChunks` 对 `js/(core|lib)/` 整目录
  返回 `'core'`,放进去会被并入稳定 chunk、boot 即加载,惰性就失效了。
  新开 `js/locales/` 目录不命中任何规则,自成小 chunk;
- **应用字典静态 import**(zh 用户也随应用 chunk 下载,每应用约 1–3KB,
  全体合计 ~50KB 分散在各自 chunk):换取"首开窗口零额外 await"。若日后
  在意,可改 mount 时按 locale 动态 import,属纯优化。

清单示例(仍纯数据,不 import 任何东西):

```js
export default {
  id: 'memo', name: '笔记', desc: '卡片式笔记,支持加密与置顶',
  category: '效率',
  i18n: { en: { name: 'Notes', desc: 'Card notes with encryption & pinning' } },
};
```

- registry 提供 `appName(id)` / `appDesc(id)`:返回当前 locale 的清单名,
  `i18n` 字段缺省回落 `name`/`desc`;
- **`category` 保持中文值不变**(它是商店过滤的身份,源码常量,稳定性与
  运行时语言无关):商店侧栏 `CATS` 的 label、卡片上的分类显示走
  `t(category)`,六个值的译文进 `js/locales/en.js`。第三方应用约定使用
  这六个已知值;英文书写习惯的第三方可在 `i18n` 里补 `category` 映射
  (实现期再定细节)。

## 6. 设置与切换流程

- `core/store.js` 的 `DEFAULTS` 增加 `locale: 'zh-CN'`(**明确默认中文,
  不默认 auto**——存量用户全中文,e2e 也依赖默认 zh);可选值
  `'auto'`(解析 `navigator.language`,非 en 家族回落 zh-CN);
- 设置应用「系统」节增加下拉:跟随浏览器 / 简体中文 / English;
- **用户路径**:下拉选择 → 确认框「重启系统以应用语言?」→
  `settings.set({ locale })` → `location.reload()`;
- 安全性:与用户按 F5 完全等价——会话恢复(`sessionRestore` 默认开)把
  打开的窗口原样开回来,应用重挂载即新语言;应用数据各有防抖落盘,
  无新增丢失面;
- **boot 接入**:启动序列在 `applyAllSettings()` 之后、渲染外壳(第 6 步)
  之前 `await ready()`:解析 locale → `document.documentElement.lang` →
  en 则动态加载 `js/locales/en.js`;
- 切换仍广播 `sys:locale-changed`(载荷 `{ locale, tag }`),供未来现场
  重绘消费;**v1 的生效方式就是重启**,语义上贴合 WebOS 题材,并完全避开
  "每个应用都要实现现场重绘"的工程量。外壳模块(taskbar/startmenu/tray/
  desktop,均小文件、各有 render)的现场重绘列为 v2 增强;应用级现场切换
  不做承诺,应用想支持可自行订阅重绘;
- `index.html` 的静态可见文案(title 提示、placeholder)在 boot 期由 JS
  按当前 locale 设值;
- 排序与搜索联动:`registry.list()` 的 `localeCompare` 用 `localeTag()`;
  开始菜单搜索索引在 `name + id` 基础上加 en 名(`appName(id, 'en')`),
  英文用户搜 "notes" 也能命中;商店搜索串同步拼入 en 名与 en 简介;
- e2e / 自动化路径:跳过确认框,直接
  `WebOS.settings.set({ locale: 'en-US' }); location.reload()`。

## 7. 显示名与桌面快捷方式

`appName()` 的消费点清单(wm 标题、任务栏、开始菜单、商店、applink 菜单
与「发送到桌面」通知、openwith)在 P0 一次性替换。

**`.app` 快捷方式文件名恒为清单默认名(zh 规范名)**:`applink.js` 的
播种/查重/卸载清理零改动。这是刻意决策——若文件名跟语言走,会同时引入
"换语言后按新名查重失效 → 同一应用播两个快捷方式"与"卸载按新名清理 →
旧名文件残留"两类 bug。

显示层本地化只做一处:`desktop.js` 的 `displayName()` 扩展——`.app` 条目
经 `appLinkApp()` 取目标应用,若文件名去后缀等于该应用**任一语言的默认名**
(zh `name` 或 `i18n.*.name`),显示 `appName()`(当前语言);否则(用户
已改名)原样显示。文件管家列表、终端、重命名浮层继续显示/编辑真实文件名
(`desktop.js:17-19` 注释的既有语义,不变)。

## 8. 应用接入指南(P1/P2 逐应用执行)

每个应用的接入 checklist:

1. UI 字面量包 `t()`,模板串改占位符形式;
2. 建 `js/apps/<id>/en.js`(默认导出扁平字典)并在 `index.js` 顶部
   `import './en.js'`;
3. 日期时间调用改 `fmtDate/fmtTime/fmtDateTime`;
4. **排查中文枚举入库**(memo 的 `CATS` 是已知案例):按 §3"值即标识"
   处理——值不动,显示层 t();确有值/显示需解耦的,记录进本文件的
   应用备注;
5. 跑该应用 e2e 组 + 全量(zh 恒等,理论上零影响,防手滑)。

常见改写模式:

```js
/* 条件后缀拼接 → 拆成完整文案(避免语序问题) */
setTitle(`笔记 — ${n} 条${locked ? `(🔒${locked})` : ''}`);
// →
setTitle(locked ? t('笔记 — {n} 条(🔒{k} 条)', { n, k: locked })
                : t('笔记 — {n} 条', { n }));

/* 嵌套插值 */
`输入「${memo.title}」的密码`   → t('输入「{title}」的密码', { title: memo.title })

/* title / placeholder / dialogs / notify 的每个参数都同样处理 */
el('input', { placeholder: t('搜索标题…') })
dialogs.confirm({ title: t('删除笔记'), message: t('删除「{name}」?', { name }), okText: t('删除') })
```

特殊应用:

- **terminal(`bash.js`)/ vssh**:命令名与参数语法不翻,帮助文本、用法
  报错、输出提示走 t();
- **sheet**:已有 `sortLocale` 设置与 `Intl.Collator` 消费,保持独立不动;
  界面文案(工具栏/菜单/状态提示)照常接入;
- **clues/tuxun**:界面 chrome 接入,谜题与便签**内容**属 P3。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 中文措辞修改导致译文静默失效 | `i18n:check` 闸门比对源与字典(§9) |
| 运行时拼接串不可作键 | 按 §8 模式改写为占位符/完整文案 |
| en 译文更长撑爆布局 | T62 全量截图走查 + 放宽写死宽度 |
| 中文枚举存量数据 | "值即标识"约定,零迁移(§3);新应用守约 |
| 忘包 t() 的新代码 | 回落机制保证可用;extract 工具提示裸中文清单 |
| 双语搜索/排序 | 开始菜单索引收双语名;localeCompare 用 localeTag() |
| 应用字典随 chunk 被 zh 用户下载 | 每 app 1–3KB,可忽略;在意再改动态 import(§5) |

## 12. 决策记录

| 决策 | 结论 | 一句话理由 |
|---|---|---|
| key 策略 | **中文即键**,不引入抽象 key | 渐进接入、e2e 零改动、源码可读(§3) |
