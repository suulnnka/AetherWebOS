# AetherWebOS 国际化(i18n)设计与实施计划

> 状态:**方案 v3;P0 基建已落地(2026-10-17),P1/P2/P3 未开工**。v3 修订两条:
> ①剧情**数据**(含数据库种子)按语言**每语言一份(多份)**——未来有
> 查询数据库的游戏任务,库内容本身是玩法素材;②内网站点**不复制**,
> 保持单源,经 **i18n 字典查表**在编译前替换字符串。事实基线 2026-10,
> 行号与文件均已核对。

## 1. 总览:两个语言平面

| 平面 | 决定者 | 管什么 | 可否切换 |
|---|---|---|---|
| **界面语言**(UI locale) | 系统设置 `locale` | 所有 chrome:外壳、系统对话框、各应用界面、清单名 | 随时可切(重启生效,§6) |
| **剧情语言**(game language) | **开局选择,存入 vnet 状态** | 游戏世界:剧情数据(DNS 备注/SSH 世界树/邮件短信种子/任务数据库)、内网站点的查表译文 | **游玩中锁定**;换语言 = 重开新局(§9) |

剧情层按成分分三种技术路线(§9):

| 成分 | 例子 | 路线 |
|---|---|---|
| **逻辑** | 谜题流程、标志位联动、钩子框架 | 单份,语言无关 |
| **数据** | DNS 备注、SSH 文件树、种子邮件/短信、回信与通知文案、未来任务数据库 | **每语言一份(多份)**,开局按语言取用 |
| **站点界面** | `sites/` 的 html/ajs 源码、站点 title | **单源 + i18n 字典查表**,编译前替换 |

两平面解耦的理由:剧情数据在**播种时刻**落库/注册,落定即存档,不可逆也
不该逆——已读的信不会自己换语言。语言选择点前移到开局;之后界面语言随便
切,世界内容保持开局语言。**剧情进行中切界面语言会出现"界面英文、信件
中文"的混排**,这是设计允许的状态。

数据层(用户自己的文件、笔记、表格)不翻,与平面无关。

## 2. 范围分级

| 分级 | 内容 | 路线 |
|---|---|---|
| **字典翻译**(逐串查表) | 外壳全部、系统对话框/右键菜单/登录面板/开机提示、core 报错、lib 组件串、各应用界面 chrome、终端与 vssh 本地命令帮助/输出、清单元数据、**内网站点源码与站点 title** | 单源 + 字典 |
| **数据多份**(每语言一份) | `js/game/` 剧情数据:DNS 备注、SSH 服务器树(文件/motd/banner)、种子邮件/短信、自动回信模板、通知文案;未来查询类任务数据库;应用自带内容(tuxun 照片池 title 与含文字图片) | 每语言整份数据文件 |
| **不翻** | 用户文件内容、应用数据落盘值、控制台调试、`window.WebOS`、vendor 引擎 | — |

RTL 不做(两语言均 LTR),字典结构预留 `dir`。

## 3. 现状盘点(方案的事实依据)

UI 字符串量级(引号内含中文字面量粗扫):core ~334 / system ~125 /
lib ~86 / apps ~2003;`js/game/` 剧情与站点另有整段叙事文本。

关键消费点:

- **清单名是全局显示源**:`manifest.name` → wm 标题/任务栏/开始菜单
  (含 `data-search` 搜索索引,`startmenu.js:33` 只收 `name+id`)/商店卡片/
  applink 菜单;
- **`category` 是身份**:商店过滤按中文值相等比较(`appstore/index.js:75,199`);
- **快捷方式文件名 = 清单名**:`applink.js` 播种/查重/卸载全以中文名为
  路径键;桌面渲染只去 `.app` 后缀(`desktop.js:19`);
- **日期硬编码 `'zh-CN'`** 散落(memo/mail/clues/weather);
- **settings 基建**:`settings.set → sys:settings-changed` 广播已有;
  `sortLocale` 排序设置跟随剧情语言走(设置界面不暴露,e2e 经
  `WebOS.settings` 直改);
- **e2e 依赖中文文本**:上百处按 `textContent` 找按钮,全部用例默认 zh;
- **剧情层结构**(`js/game/`):`index.js` 是游戏编排——DNS 注册(中文
  note)、两台 SSH 服务器整棵中文文件树、`mail.onFirstUse` 种子信件、
  `sms.hydrate()` 后种子短信、`onSend` 自动回信、通关邮件与通知,逻辑与
  叙事数据混写在同一文件;`site-defs.js` 站点元数据(title 中文);
  `sites.js` 用 `import.meta.glob('./sites/**/*.{ajs,html}')` 把站点源码
  按目录注入 SITE_DEFS;`core/aethersite.js` 沙盒编译挂载;Node 冒烟
  `tools/aether-sites-smoke.mjs` 直接读磁盘同源;
- **剧情状态**:`webos.vnet.v1`(localStorage),已有 `vnet.resetState()`
  整机重置;邮件按邮箱身份成库、短信设备级库——种子写入即数据;
- **图片资产**:仓库唯一图片池是 tuxun 的 `apps/tuxun/photos/`
  (svg + 登记表,title 中文);站点无图片;
- **中文枚举入库**:memo 分类等(§4 值即标识)。

## 4. 核心决策:中文即键(gettext 式,一切字典平面)

`t('新建')` 在 zh 下恒等返回,en 下查字典回落键。不引入抽象 key。

1. **渐进无风险**:未翻译回落中文,可逐应用接入,无需 130 文件大爆炸;
2. **e2e 零改动**:默认 zh 恒等,既有用例照旧;
3. **源码可读**:`t('删除笔记')` 优于 key 命名,无漂移 review 负担;
4. 抽象 key 要求一次性重写全部字符串与 e2e,本仓库规模不可行。

**站点查表沿用同一约定**(§9.4):字典键 = 站点源码里的中文字符串原文,
en 字典 zh→en 整串替换——同一套心智模型、同一套提取校验工具。

**引申约定:持久化枚举值以中文值为稳定标识**(memo 分类、商店 category
同理):值进数据作身份、显示层 t()、比较逻辑用原值 → 存量数据零迁移。
代价是数据格式与文案耦合,宁可不改这类文案。

## 5. 字典组织:每个单元自有 i18n/

**每个代码单元把自己的翻译放在自己目录里**,谁的字串谁维护,删应用即删翻译:

```
js/core/i18n/en.js        # 内核字典(dialogs/fs/wm 报错与提示…)
js/system/i18n/en.js      # 外壳字典(任务栏/开始菜单/托盘/桌面/boot…)
js/lib/i18n/en.js         # 组件库字典(mdedit/chl/minimap…)
js/apps/<id>/i18n/en.js   # 各应用自己的字典(随应用 chunk)
js/game/i18n/en.js        # 站点字典(站点源码与站点 title 的整串替换表,§9.4)
```

- 字典文件自注册:文件内部 `import { registerDict } from '…/i18n.js'` 并
  调用,**引用方只需一行静态或动态 import**;
- **应用字典**:应用 `index.js` 顶部 `import './i18n/en.js'`,并入该应用
  chunk(每应用 1–3KB,zh 用户也随 chunk 下载,换取首开零 await);
- **core/system/lib/game 字典**:zh 用户不加载。boot 期为 en 才**动态
  import**(加载点统一在 `js/system/boot.js` 装配层;game 字典按剧情语言
  而非界面语言决定是否加载,§9.4);
- **打包豁免(必须)**:manualChunks 对 `js/(core|lib)/` 整目录返回
  `'core'`,字典放里面会被并进稳定 chunk。在 worker 豁免
  (vite.config.js:63)旁补一条:
  `if (/[\\/]js[\\/](core|lib)[\\/]i18n[\\/]/.test(id)) return;`
  (`js/system/`、`js/game/` 本就不匹配任何规则,规则里带上只为统一);
- zh 无字典:回落即键,不存在 `zh.js`。

清单元数据(仍纯数据):manifest 增加 `i18n` 字段,registry 提供
`appName(id)/appDesc(id)`:

```js
export default {
  id: 'memo', name: '笔记', desc: '卡片式笔记,支持加密与置顶', category: '效率',
  i18n: { en: { name: 'Notes', desc: 'Card notes with encryption & pinning' } },
};
```

`category` 保持中文值作身份不变,显示层 `t(category)`,六个值的译文进
`js/core/i18n/en.js`。第三方应用约定用这六个已知值。

运行时 `js/core/i18n.js`(进稳定 chunk,几十行,依赖 store/bus):

```js
t('新建')  t('共 {n} 条', { n })  tn('{n} 条', n)      // 复数预留
registerDict('en', tbl)  currentLocale()  localeTag()  // 'auto' 已解析为 BCP-47
onLocaleChange(fn)  ready()                            // boot:解析 locale、设 <html lang>
fmtDate/fmtTime/fmtDateTime                            // 替代散落的 'zh-CN'
```

## 6. 设置与切换(界面语言)

- `DEFAULTS.locale = 'zh-CN'`(明确默认中文;`'auto'` 可选,非 en 家族
  回落 zh-CN)。设置应用「系统」节加下拉:跟随浏览器 / 简体中文 / English;
- 用户路径:下拉 → 确认「重启系统以应用语言?」→ `settings.set({ locale })`
  → `location.reload()`。与 F5 等价:会话恢复开回窗口,应用数据有防抖落盘;
- boot 接入:`applyAllSettings()` 后、渲染外壳前 `await ready()` +
  按需加载字典(§5),`index.html` 静态可见文案同步设值;
- 广播 `sys:locale-changed`(载荷 `{ locale, tag }`);v1 生效方式=重启,
  外壳现场重绘(taskbar/startmenu/tray/desktop 各有 render)留 v2;
- `registry.list()` 的 `localeCompare` 改用 `localeTag()`;开始菜单搜索
  索引补 en 名(搜 "notes" 命中「笔记」);商店搜索串拼入 en 名/简介;
- e2e/自动化:`WebOS.settings.set({ locale: 'en-US' }); location.reload()`
  跳过确认框;
- **剧情语言不在此下拉里**:入口是开局向导与「重置剧情」(§9.3)。

## 7. 显示名与桌面快捷方式

`appName()` 消费点(wm 标题/任务栏/开始菜单/商店/applink 菜单与「发送到
桌面」通知/openwith)在 P0 一次性替换。

**`.app` 文件名恒为 zh 规范名**,`applink.js` 播种/查重/卸载零改动——
文件名跟语言走会同时引入"重复播种"与"卸载残留"。显示层只动一处:
`desktop.js displayName()` 扩展:`.app` 条目经 `appLinkApp()` 取目标应用,
文件名去后缀等于该应用**任一语言默认名**时显示 `appName()`,用户改过名
则原样。文件管家/终端/重命名继续用真实文件名(`desktop.js:17-19` 语义)。

## 9. 剧情层:逻辑单份 / 数据多份 / 站点查表

### 9.1 目录结构

`js/game/` 按「逻辑 / 数据 / 站点」三分,逻辑与数据解耦:

```
js/game/
├── index.js          # 剧情逻辑(单份,语言无关):注册 DNS/SSH、挂钩子、
│                     #   播种种子的流程;一切文案从 data 取
├── data/             # 剧情数据(每语言一份,多份)
│   ├── zh-CN.js      #   DNS 表(含 note)、SSH 服务器树(文件/motd/banner)、
│   └── en-US.js      #   种子邮件/短信、回信与通知文案、(未来)任务库种子
├── sites/            # 站点源码(单源,现结构不动:router.ajs/*.html/*.ajs)
├── site-defs.js      # 站点元数据(title 经站点字典翻译,§9.4)
├── sites.js          # glob 注入(不动)
└── i18n/
    └── en.js         # 站点字典:站点源码与 title 的 zh→en 整串替换表
```

- **逻辑单份**:`index.js` 只写流程(何时播种、标志位联动、邮件何时发),
  不含具体文案;同一份逻辑驱动任何语言;
- **数据多份**:`data/<lang>.js` 导出**同构**(相同字段结构)的完整剧情
  数据,加语言 = 复制 `zh-CN.js` 为 `en-US.js` 整份翻译。数据是纯对象,
  复制粘贴即得,不需要抽键——库里的信是成段叙事,整段住在数据文件里
  最直接;
- **站点单源**:`sites/` 只有一棵树(现结构、现路径、smoke 读盘路径都不动)。

### 9.2 数据库:源多份,开局按语言播种

- **源多份**:种子邮件/短信、回信模板、通知文案在 `data/<lang>.js` 里
  每语言一份;未来**查询类任务数据库**(玩家在数据库应用里跑 SQL 找线索
  的玩法)同样每语言备一份种子数据——库内容本身是玩法素材,必须随语言
  整份准备,不能运行时翻译(译文进不了 SQL 结果的语境,且作者要能按
  语言控制线索措辞);
- **运行时一份**:开局选定剧情语言后,`mail.onFirstUse` /
  `sms.stats().msgs === 0` 的播种时机(`game/index.js:190,227`)读
  `data[gameLang]` 落库一次,落库即存档,此后永不跟随语言变化——已读的
  信不会自己换语言。**库里永远只有一种语言,但源码里每种语言各备一份**;
- 未来任务库的挂载同理:任务解锁时把 `data[gameLang]` 对应的库种子
  物化到 VFS(如 `/home/shared/quest/…`),玩家查询的就是开局语言的库;
- 换剧情语言 = 重置剧情重播(§9.3),新局按新语言重新播种。

### 9.3 开局选语言与锁定

- boot 时 vnet 状态无 `gameLang`:弹出**剧情语言选择**(开机向导式,
  简体中文 / English,默认跟当前界面语言),选定写入 `webos.vnet.v1`,
  再加载对应 `data/<lang>.js` 与站点字典;
- `?e2e=1` 与 `#open=` 模式**跳过向导**(预置 zh-CN),既有 60 组 e2e
  与无头比对不受影响;
- **游玩中不可切**:设置应用不提供剧情语言项;想换语言 = 系统设置
  「重置剧情世界」——扩展 `vnet.resetState()`:清 flags + `gameLang` +
  邮件/短信库的种子标志(用户自建内容是否保留,实现期定),下次 boot
  重新走向导、按新语言重播;
- 界面语言与剧情语言独立:切界面语言不影响已播的世界内容(§1 混排说明);
  站点译文随剧情语言(§9.4),不随界面语言。

### 9.4 内网站点:单源 + 查表替换

- **站点源码不动**:`sites/` 保持单棵中文树,作者照常写中文模板与处理
  函数,不需要在沙盒里调 t(),AetherWebFramework 与沙盒白名单**零改动**;
- **字典**:`js/game/i18n/en.js` 是站点源码的 zh→en **整串替换表**,键
  与源码中的中文字符串逐字一致(§4 同一约定);
- **替换时机**:aethersite 编译前预替换——`core/aethersite.js` 在把源码
  交给沙盒编译前,若剧情语言非 zh,按字典对源码文本做**整串精确替换**
  (静态 HTML 与 `.ajs` 模板字面量里的中文段统一处理,编译产物即英文);
  `site-defs.js` 的 `title` 走同一张表;
- **键的粒度**:以"完整文案段"为键(整句/整个标签内文本),不做子串
  模糊替换——避免部分命中改错;含插值的模板串按其静态段拆键
  (如 `'馆藏总量:'`、`' 册'`);
- **校验闸门**(§11):提取工具扫描 `sites/` 的中文字符串对照站点字典,
  报"源有译无/译有源无";smoke 对替换后的 en 源码做编译校验,并可断言
  **替换产物无残留中文**(字典完备性的强不变量);
- 站点内若有图片(现无):无字图共用,含字图分语言(同 §8.4);
- 第三方站点作者:照常写中文站点,补字典条目即可获得英文版,无第二个
  目录要维护。

## 10. 内网站点 i18n(要点重述)

- 单源 `sites/` + `game/i18n/en.js` 查表,aethersite 预编译整串替换,
  沙盒零改动(机制见 §9.4);
- 站点渲染语言 = **剧情语言**(开局锁定),浏览器标签页 title、起始页
  「内网站点」列表、DNS `note` 均随之;
- `tools/aether-sites-smoke.mjs` 扩展:对**两个语言**各跑一遍
  (zh 原文编译、en 替换后编译),en 断言无残留中文;
- `sites.js` 的 glob 与读盘路径完全不动(对比 v2 的双树方案,此路
  目录结构零迁移)。

- 剧情数据(`game/data/*.js`)不进此工具(整份多备,无键可比);两份
  数据的**结构对齐**靠导出同构约定 + smoke 引用字段跑通兜底;
- `aether-sites-smoke.mjs` 双语言遍历(§10);
- e2e 新组 T64(编号因 T62/T63 被任务栏/落盘组占用顺延):界面语言切 en(断言外壳/商店/示例应用/日期格式)后切回;
  剧情平面组(P3,编号届时定):`--clean` 全新 profile → 断言开局向导出现 → 选
  English → 断言 DNS note/种子邮件/内网站点为英文 → 重置剧情 → 选回中文。
  既有用例跑在预置 zh-CN 的向导跳过路径上,不受影响;
- en 布局走查一轮 `.shots/`(英文更长,任务栏/开始菜单/商店/设置/表格
  工具栏,排查写死宽度)。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 中文措辞修改致 UI 译文失效 | i18n:check 比对源与字典 |

## 14. 决策记录

| 决策 | 结论 | 一句话理由 |
|---|---|---|
| key 策略(一切字典平面) | **中文即键**(站点替换表同约定) | 渐进、e2e 兼容、可读、工具统一(§4) |
| 字典归属 | **每单元自有 `i18n/` 目录**(core/system/lib/apps/game),应用字典随应用 chunk | 谁的字串谁维护,删应用即删翻译(§5) |
| 界面语言切换 | **v1 重启式**,现场重绘留 v2 | 与 F5 等价,避开全应用重绘(§6) |
| 剧情逻辑 | **单份**,文案从 data 取 | 流程与语言无关(§9.1) |
| **剧情数据(含数据库)** | **每语言一份(多份)**,开局按语言播种,运行时一份 | 查询类任务库里内容是玩法素材,必须整份随语言备;落库即存档不可逆(§9.2) |
| **内网站点** | **单源不复制 + 字典查表**,aethersite 编译前整串替换,沙盒零改动 | 站点是界面性内容,查表即可,免去双树维护(§9.4) |
| 剧情语言 | **开局向导选定并锁定**,换语言=重置剧情 | 播种不可逆;游玩中切换必然造成半中半英存档(§9.3) |
| 图片 | **无字图共用,含字图分语言** | 避免无谓 ×2(§8.4) |
| category/持久化枚举 | **中文值即标识,显示层翻译** | 过滤逻辑与存量数据零改动(§4) |
| 默认界面语言 | **zh-CN 明确默认** | 存量用户与 e2e 依赖(§6) |
| 快捷方式文件名 | **恒为 zh 规范名,显示层本地化** | 避免重复播种/卸载残留(§7) |
